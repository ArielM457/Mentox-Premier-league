# **Evaluación y evidencias**

La rúbrica compartida asigna 20 % a cada uno de cinco criterios. Estas reglas guían el trabajo y la preparación de la demo. No son resultados obtenidos todavía.

## **1. Implementación tecnológica · 20 %**

Debemos mantener código organizado, documentación que permita ejecutar el proyecto y pruebas de las transformaciones importantes. La demo debe mostrar qué tecnología se usa y para qué sirve. Las estadísticas no deben depender de texto generado por IA cuando puedan calcularse directamente de los eventos.

Evidencia esperada: repositorio comprensible, instrucciones de ejecución, ejemplo reproducible y pruebas de cálculos y contratos de salida.

## **2. Diseño de agentes e innovación · 20 %**

Debemos usar IA para una tarea con valor real, como elegir, explicar o adaptar narraciones a partir de un estado verificable. Si elegimos varios agentes, cada uno debe tener una responsabilidad clara y una forma de resolver conflictos. El número de agentes no es un objetivo por sí mismo.

Evidencia esperada: flujo visible desde eventos hasta narración, papel concreto de cada agente o etapa, y ejemplos donde la IA aporta más que una plantilla fija.

## **3. Impacto y aplicación real · 20 %**

Debemos mostrar a quién ayuda la solución y cómo podría entrar en un flujo de estudio, transmisión o streaming. Debemos medir el tiempo de salida y documentar fallos, límites de los datos y pasos que faltarían para producción.

Evidencia esperada: caso de uso concreto, formato de integración, medición de latencia y lista honesta de pasos pendientes para operar con una transmisión real.

## **4. Experiencia y presentación · 20 %**

Debemos presentar una interfaz clara y un recorrido que se entienda sin explicar internamente cada cálculo. La demo debe enseñar entrada, contexto, explicación, salida en pantalla y personalización. El backend y el frontend deben funcionar juntos.

Evidencia esperada: reproducción de un partido, comparación de modos, cambio de preferencias y resumen final generado desde el mismo flujo.

## **5. Ajuste a la categoría · 20 %**

Debemos cubrir las cinco etapas del reto con eventos sintéticos realistas. La solución debe producir información explicable durante el partido y un resumen automático. La personalización debe cambiar la experiencia de forma visible.

Evidencia esperada: trazabilidad entre eventos, estadísticas, explicación, mensaje temporizado y presentación personalizada.

## **Reglas de revisión antes de entregar**

**1.** Cada afirmación de la demo debe corresponder a una función probada o identificarse como propuesta.

**2.** Cada mensaje importante debe tener datos de origen revisables.

**3.** La demo debe funcionar con datos sintéticos incluidos en el proyecto.

**4.** Debemos revisar la experiencia completa en ejecución, no solo la compilación.

**5.** Debemos mostrar tanto un caso normal como al menos un límite o fallo controlado.
