# Evidencias de desarrollo

Guardar aquí las nuevas comprobaciones que necesiten conservarse junto al repositorio. El archivo anterior, incluido el material de Persona 1, se conserva localmente en `docs-anteirores/` y en el historial Git; no es una dependencia de las guías actuales.

Cada evidencia debe incluir:

1. Fecha, rama/commit base y cambios locales relevantes.
2. Especificación y criterios de aceptación cubiertos.
3. Fuente de datos, permiso/licencia cuando corresponda, semilla y hashes.
4. Versiones, variables de configuración sin secretos y dependencias externas.
5. Comandos, resultados, duración relevante y archivos de salida.
6. Fallos, límites y lo que no se verificó.

Usar nombres como `AAAA-MM-DD-modulo.md`. Las capturas o informes grandes deben mantenerse en un directorio de artefactos adecuado, con referencia y checksum cuando sea necesario. No guardar secretos, vídeos sin permiso ni enormes registros de ejecución dentro de Markdown.

La revisión documental del 28 de octubre se registra en [validación](../validacion.md). Una casilla de tareas implementada no reemplaza esta evidencia.
